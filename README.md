# Cloudflare Access Seat-Equivalent Allocation Demo

Design for a customer-deployable visualization and export tool mapping observed successful Cloudflare Access logins to applications. It splits one observed user's seat-equivalent across distinct application-owning teams and gives Finance reproducible evidence for internal allocation decisions. It does not determine contractual billable seats, reconcile invoices, or approve monetary charges.

Current status: deployable prototype code is present. It still needs a Cloudflare account context, D1 database ID, Worker Access policy, and remote migration/deployment in the target account.

Assume in-scope applications have 24-hour sessions. The planned viewer must prominently disclose that existing-session activity and reporting-period boundary activity may be absent from login-based attribution. See the PRD for the exact disclaimer, separate team/detail exports, and required report context.

Architecture:

```
Cloudflare Access access_requests Logpush -> R2 -> scheduled Workflow -> D1 -> Access-protected viewer Worker
```

Start with [docs/prd.md](docs/prd.md) and [docs/solution-architecture.svg](docs/solution-architecture.svg).

Key decisions:

- Use Access application ownership tags, not user groups, for team seat-equivalent allocation.
- Export additive team totals separately from permission-controlled user-application relationships; do not duplicate team shares across application rows.
- Retain each export's period/timezone, generation/data-as-of times, coverage status, rule version, ownership mapping, and applied exclusions/settings.
- Use a scheduled Workflow instead of a single cron Worker, so ingestion can process R2 in bounded cursor-based batches.
- Keep R2 notifications and Queues out of MVP because monthly visualization and Finance review do not need per-file real-time ingestion.

## Implementation status

The repository includes a prototype Worker and scheduled Workflow implementation:

- `src/index.ts`: viewer Worker plus scheduled Workflow ingestion.
- `src/lib.ts`: Access log parsing and allocation SQL helpers.
- `migrations/0001_initial.sql`: D1 schema including ingestion state, normalized events, usage, ownership snapshots, and export context.
- `wrangler.example.jsonc`: Worker, Workflow, R2 and D1 binding template. Copy it to `wrangler.jsonc` (gitignored) and fill in account-specific values.
- `docs/deployment-guide.md`: reusable deployment guide for any Cloudflare account.

Copy `wrangler.example.jsonc` to `wrangler.jsonc` and configure the R2 bucket binding and account-specific IDs before deploying.
